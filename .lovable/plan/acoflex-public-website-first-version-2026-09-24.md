# Acoflex Public Website — First Version

## Goal
Create a complete, photography-led public website for Acoflex that feels editorial, established, and distinctly industrial—not like a dashboard or generic corporate template. Use only information supported by the current Acoflex website.

## Visual direction
- Treat the selected “Cooled glass editorial” concept only as a loose starting point.
- Build a more art-directed system around large-scale factory and product photography, confident typography, generous whitespace, hard editorial crops, and asymmetric composition.
- Use a restrained industrial palette with mineral white, carbon, Acoflex blue, and a small safety-red accent drawn from the current identity.
- Avoid gradients, decorative blobs, glass panels, fake schematics, repeated card grids, invented product renders, and UI-heavy technical decoration.
- Use measured image reveals, typographic transitions, and restrained hover motion with reduced-motion support.

## Pages and structure
- **Home:** Brand statement, product families, manufacturing story, material/quality principles, distribution and enquiry pathways.
- **About:** Company profile, markets served, values, and supported differentiators.
- **Products:** Filterable catalogue sourced from six verified product categories.
- **Product detail:** One reusable dynamic page template driven by shared product data, with descriptions and known applications only; unavailable specifications and documents will not be fabricated.
- **Manufacturing:** Process-led story using the eight named production and facility capabilities from the source site.
- **Quality / Technology:** Verified material and testing claims, clearly written without unsupported certifications.
- **Infrastructure:** Extrusion plant, testing lab, storage, and logistics story.
- **Dealer / Distributor:** Verified dealer benefits and a clear enquiry path; no invented locator or network counts.
- **Resources:** A carefully designed resource hub that truthfully states when technical documents are not yet published, rather than creating fake downloads.
- **Contact:** Verified address, hours, and published email channels. Omit placeholder phone numbers. A front-end enquiry experience will route users to email without pretending submissions are stored.
- **FAQ:** The four questions and answers currently published, edited only for clarity.

## Content and product architecture
- Create a single reusable static data layer for navigation, product categories, process steps, FAQs, and contact information.
- Use dynamic `/products/$slug` pages for all six product families and related-product navigation.
- Preserve factual gaps: no invented SKUs, diameters, pressure classes, standards, certificates, warranties, prices, dealer totals, capacities, company age, or technical PDFs.
- Use source-site imagery as the initial visual library, downloaded and stored through the project asset system for reliable serving and easy future replacement.

## Shared experience
- Build a distinctive shared header, mobile menu, footer, breadcrumb treatment, editorial section headings, image treatments, and enquiry calls-to-action.
- Ensure navigation, filters, accordions, forms, and product links work on desktop and mobile.
- Add unique search/social metadata for every public page and dynamic product page.

## Validation
- Verify all routes and interactions in the running site.
- Review representative desktop and mobile screenshots for hierarchy, image crops, text fit, navigation, and overlap.
- Confirm no placeholder template remains and no unsupported claims were introduced.

## Deferred by request
- Admin dashboard, CMS, authentication, profiles, media management, database, stored leads, and all backend work.
